# Процесс работы и инсайты

> См. также: [Архитектура](architecture.md) · [Окружение](dev-environment.md)

## Оркестрация агентов (AGENTS.md, STRICT)

Код правится **только** сабагентами; главная нить — разбор, вопросы (`question`), декомпозиция, сборка, валидация.

| Агент | Роль |
|---|---|
| `cavecrew-investigator` | поиск: где определено, кто вызывает |
| `cavecrew-builder` | правки ≤2 файлов; большой объём — нарезать на параллельные подзадачи |
| `frontend-developer` / `kotlin-backend-developer` | фича целиком на своей стороне |
| `cavecrew-reviewer` | аудит диффа после правок |

Рабочий цикл фичи: **декомпозиция → параллельные фичевые агенты → ревью → фикс-проход builder'ами → обе сборки**. Независимые файлы — разные builder'ы параллельно; согласованность сигнатур между файлами фиксируется в промптах обоих агентов дословно (пример: конструктор `PolynomClient(httpClient, authProvider, tokenManager)`).

Документация/знания сессии допустимо писать главной нитью — делегирование означало бы переписывание контекста в промпт с потерями.

## Архитектурные инсайты сессии

1. **Кто пингует — тот и отвечает.** Проверки доступности из Next.js-сервера бессмысленны: они измеряют коннективность хоста Next, а не точки, через которую идёт реальный трафик. Правильная точка — Kotlin BFF. Следствие: `/connections` живёт в бэке, фронт только рисует.
2. **Единая точка адресов.** Один `polynom.base-url` в `application.conf` кормит и `defaultRequest` (относительные пути всех вызовов), и refresh-эндпоинт (абсолютный URL). Хардкоды хоста в коде — долг с гарантией рассинхрона.
3. **Стартовая не зависит ни от чего.** Публичные страницы (`/`, `/connections`, `/polynom/auth`) рендерятся при любом состоянии сети; все данные — фоновые react-query, ошибки — состояния UI, не краш.
4. **Auth per-service.** Общего логина нет: `/polynom/auth` — подключение именно Polynom (хранилище → креды). Новый сервис копирует паттерн: свой маршрут, свой степпер, свой guard-зонт.
5. **Guard через layout + route group.** `(protected)`-группа закрывает дерево маршрутов одним layout'ом, URL не меняются; точка входа (auth) — вне guard.
6. **Рефакторинг мёртвого — часть фичи.** Дублирующий TokenManager, неиспользуемые константы AuthConfig, хардкоды портов — находились ревью и удалялись в рамках той же итерации.
7. **Guard не решает по протухшим данным.** `invalidateQueries` лишь помечает кэш — при маунте guard увидит старый `{authenticated:false}` и уйдёт в редирект раньше, чем фоновый refetch вернёт правду (реальный баг: цикл logout→login→`/polynom/auth`). Лечение: сессионный кэш после логина — `removeQueries` (маунт даёт спиннер + живой запрос), в guard'е редирект только при завершённом запросе (`!isFetching`). SPA-выход с очисткой состояния надёжнее делать полной перезагрузкой страницы.

## Типовые находки ревью (чек-лист для новых фич)

- Гонки: свой `AbortController` на каждый fetch + аборт предыдущего; setState после unmount; двойной сабмит (Enter минус disabled-кнопка → `if (isPending) return`)
- Таймауты у всех fetch (иначе вечный spinner): `AbortSignal.timeout(...)`
- `CancellationException` пробрасывать в catch-блоках корутин, не глотать
- react-query кеш переживает навигацию: логин-мутации синхронизируют затронутые кэши сами (`removeQueries(['session'])` в onSuccess authorize); logout — `window.location.assign('/')`, не `queryClient.clear()` после `router.push` (живой guard успевает отрефетчить 401 и перебить навигацию)
- Exhaustive-маппинги union'ов с fallback (`STATUS_META[status] ?? ...`) — контракт со строковым полем не гарантирован компилятором
- Ошибки бэка читаются по обоим ключам (`message`/`error`)
- Ktor: `call.sessions.clear<T>()` — reified; `Socket().use`; resource-блоки на всех путях (connect/error/timeout)
- Stale-кеш `.next` после удаления маршрутов → `rm -rf .next`

## Открытые вопросы

- Публичный `/connections` отдаёт host:port инфраструктуры анонимам ([Мониторинг](connections-monitoring.md)) — ок для dev, при хостинге урезать анонимный payload
- `InMemorySessionStore` — сессии умирают с рестартом бэка; персистентность не требуется, но помнить при отладке «слетевшего» логина
- Заглушки стартовой («Новый сервис», «Новый API») — точки роста платформы за пределами Polynom
